# Collision JSON Format

Generated by `extract_collision.py` from FFXI DAT files (MZB chunks).

## File location

```
data/collision/<zone_id>.json
```

Deployed to `<ashita_install>/config/addons/mapper/collision/<zone_id>.json` for runtime use.

## Schema

```json
{
  "zone_id": 107,
  "metadata": {
    "source": "MZB",
    "vertex_count": 106867,
    "triangle_count": 140586
  },
  "bounds": {
    "min": [-760.0, -240.0, -50.0],
    "max": [800.0, 920.0, 70.86]
  },
  "vertices": [
    [x, y, z],
    ...
  ],
  "triangles": [
    [i0, i1, i2],
    ...
  ]
}
```

### Coordinate system

All coordinates are in **Ashita LocalPosition space**:

| JSON axis | Ashita axis | Direction      |
|-----------|-------------|----------------|
| `x`       | `LocalPosition.X` | East/West  |
| `y`       | `LocalPosition.Y` | North/South (horizontal) |
| `z`       | `LocalPosition.Z` | Elevation (up) |

Derivation from MZB grid-mesh transform:
- `x = V.X` (column 0 of the 4×4 matrix applied to local vertex)
- `y = -V.Z` (column 2, negated — maps MZB Z to Ashita Y)
- `z = V.Y` (column 1, already pre-negated in MZB storage — maps to Ashita Z elevation)

### Walkability filter

Only triangles whose face normal has an upward (Z) component ≥ cos(45°) ≈ 0.707 are
included. Vertical walls, ceilings, and underside geometry are excluded.

### Index format

`vertices` and `triangles` use 0-based indices. `geometry_provider.lua` converts to the
1-based `{v0, v1, v2}` triangle table at load time.

## VTABLE/FTABLE file ID formula

Zone terrain file IDs follow:
- Zones 0–255:    `file_id = zone_id + 100`
- Zones 256–999:  `file_id = zone_id + 83635`
- Zones 1000–1299: `file_id = zone_id + 66911`

ROM path from VTABLE/FTABLE:
```
vt = VTABLE[file_id]           # 1 byte
ft = FTABLE[file_id * 2]       # uint16 LE
if vt == 1: path = "ROM/{ft>>7}/{ft&0x7F}.DAT"
else:        path = "ROM{vt}/{ft>>7}/{ft&0x7F}.DAT"
```
